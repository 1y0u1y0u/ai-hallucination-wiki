Loop / Graph 設計

不是只讓 AI 一次做完，而是將每個容易出錯的節點前面加上檢查門檻（QA gate）。

蒐集五份資料B · Source Intake
→
G1 來源檢查可讀、相關、可追溯
→
Ingest Wiki建立摘要與概念頁
→
G2 Wiki Lint來源／交叉連結
Query Wiki教學大綱與頁面映射
→
G3 主張查核每個論點對應 S01–S05
→
生成 HTML可瀏覽、互動與 RWD
→
G4 UI 測試按鍵、畫面、外部連結

哪些地方會重新執行？

Loop 1｜G1 失敗 → 回到資料蒐集

若來源不相關、未提供原始連結或內容不可靠，換來源或補充資料再 ingest。

Loop 2｜G2 失敗 → 回到 Wiki 整理

若概念頁缺引用、來源關係不明、出現矛盾，先修 Wiki，不急著做投影片。

Loop 3｜G3 失敗 → 回到 Wiki Query

若簡報中的斷言找不到證據，重新查詢 Wiki，修內容後才排版。

Loop 4｜G4 失敗 → 回到 HTML

若只有切頁、鍵盤或手機版問題，僅修 CSS/JS，不重新蒐集全部資料。

反思：把檢查往前移

示範風險：AI 可能寫出「使用 RAG 就能完全消除幻覺」。這比來源所說的「降低風險」更絕對。
防線前移：在 G3 先做「單頁主張 ↔ Wiki 概念頁 ↔ 來源 S ID」對照，沒有證據先修內容再製作精美畫面。

真實執行結果與截圖記錄請見 docs/verification-log.md，不得把示範案例當成實際測試事件。
